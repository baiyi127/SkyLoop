# 天穹循环 SkyLoop

面向国服 Dalamud API 15 / .NET 10 的伊修加德重建循环插件。基于官方 [SamplePlugin](https://github.com/goatcorp/SamplePlugin) 模板，使用 [AGPL-3.0 许可](LICENSE.md)。

当前为开发测试版本。已在国服客户端测试加载、连续两件制作、重建收藏品提交及普通购买确认扣票；完整长时间循环和不同角色的路线仍需继续验证。

## 第三方插件源安装

将以下地址加入卫月设置 → 实验性 → 自定义插件仓库，保存并刷新插件列表，搜索“天穹循环 SkyLoop”安装：

```text
https://raw.githubusercontent.com/baiyi127/SkyLoop/main/repo.json
```

安装兼容的国服 vnavmesh 后，输入 `/skyloop` 打开配置。新增宏默认使用共通宏；请填写自己的编号、选择兑换物品并记录制作位置，再开始测试。

源码与下载：[GitHub 仓库](https://github.com/baiyi127/SkyLoop) · [发布版本](https://github.com/baiyi127/SkyLoop/releases)。插件源按版本固定下载地址，后续更新保持此订阅地址不变。

### 0.1.1 宏编号修复

宏编号与游戏界面统一使用0–99，输入64会读取64号格子。0.1.0错误地减去1，可能将64号误读为63号并报空。更新后请核对队列，填写游戏界面显示的编号；个人与共通宏的原有0–99配置值保留不变。100号为无效配置，需要手动修正。

### 0.1.2 提交校验修复

NPC提交窗口改为读取客户端的实际交付请求，区分数据尚未就绪、物品匹配和确实不匹配，避免因通用窗口数组没有物品编号而误报。无法确认请求时继续等待，确认不符时仍会停止。

窗口顶部显示实际的背包提交阈值及当前提交/兑换步骤；日志记录每次流程切换的空格数、阈值、票数、配方和完成轮数。默认只有空格≤10才会触发提交；如果12格就前往NPC，请核对当前配置的阈值和本次运行的阶段记录。错误停止后不会自动重试提交。

### 0.1.3 循环制作、交互与路线修复

“本次制作成功”始终检测所选配方的实际成品，只要求相对本轮制作前增加至少1件；它会忽略旧配置中仅供“指定物品增加”使用的隐藏物品ID和数量。修复了把配方ID34472误当成检测物品、导致成品31952制作成功后仍报未增加的问题。多段宏共用本轮制作前的基准，因此成品已在前段宏完成时入包也能识别。

切换到“本次制作成功”会清除不适用的隐藏参数，界面显示实际检测的成品名称与物品ID。若共通宏64已完成全部制作，无需额外添加宏0；保留一条64并选“本次制作成功”即可。

修复第二轮开搓时重复调用“打开同一配方”导致现有窗口关闭的问题：已打开且选中正确配方时直接复用，随后仍检查制作按钮，再请求开始制作。开配方、配方列表、按钮及制作窗口等阶段现在分别显示并记录日志。

前往提交、兑换或返回制作点之前，会先关闭制作菜单并等待退出制作姿态，再开始导航。实际制作仍在进行时只等待，不强行中断；无法退出时会明确报退出姿态超时，避免仍蹲在制作状态就触发寻路卡住。

兑换确认同时核对本插件刚发起的购买、当前商店、确认框独立显示的物品编号及实际票数，兼容上方只写“换取以下道具”的普通购买确认框；不再要求物品名称必须出现在上方正文中。

兑换阈值只用于触发购买。余额达到阈值且扣除保留票数后买得起所选物品时才前往兑换；成功扣票并入包后，即使剩余票数仍高于较低的触发阈值，也会正常继续。提交奖励即将超过上限且无法兑换时明确停止，不会反复往返。

制作配方改为可搜索的下拉框，从当前客户端读取成品名称、职业和等级，支持按名称或配方编号搜索、按当前制作职业筛选。已有配方编号保持选中；“由宏自行启动制作”保留原来的配方0模式。选择配方不会自动切换职业。

提交和兑换使用天穹街固定交互站位，无需记录 NPC：提交为 `47.023697, -16, 167.64795`，兑换为 `39.386646, -16, 141.85832`。启动时自动选择当前可见的新旧阶段 NPC，到达后必要时再次识别。导航始终使用柜台前的固定站位，不会被 NPC 中心坐标覆盖。旧的手动 NPC 位置会被内置位置替换；制作点、宏和阈值保持原值。

### 0.1.4 库啵好运票上限确认修复

修复提交时出现“库啵好运票的持有数量已达上限，递交该道具无法获得新的库啵好运章”确认框后误报非预期窗口的问题。仅在本插件已经发出交付、所选物品和提交 NPC 上下文均有效、完整提示匹配时自动确认，随后仍检查物品减少和振兴票增加。

“背包与兑换”新增“库啵好运票已满时继续提交（放弃新好运章）”开关，默认开启。关闭后遇到上限提示会停止并提醒先刮奖。此开关只允许放弃新好运章；若同时出现天穹票或其他奖励溢出提示，仍停止处理。

### 0.1.5 装备自动自行维修

默认在每轮制作之间检查当前穿戴装备的最低耐久度；严格低于10%时，先正常退出制作姿态，再打开自行维修窗口，只修理“装备中”分类。预检已练的对应生产职业等级与暗物质，支持用高阶暗物质替代低阶。维修完成后核对原低耐久装备身份及耐久度确实恢复，关闭本次维修窗口并继续循环。宏组尚未结束时不抢修，不改变配方、职业或返回制作点。

窗口顶部显示最低装备耐久，“背包与兑换”可关闭自动维修。暗物质不足、维修职业等级不足、装备或窗口归属改变、未知确认及超时会明确停止；不会自动购买暗物质或改为NPC维修。新增维修流程已完成国服API15编译和隔离测试，仍待游戏内实测。

## 已实现

- 共通/个人宏按游戏格子显示的 **0–99** 编号组成可增删、启停、上下排序的队列，64号格子直接填写64。
- 直接调用游戏的宏模块，不模拟键盘。先确认宏确实执行并结束，再判断配置的完成条件；支持宏执行结束、制作成功、指定物品数量增加。
- 在可搜索的下拉框选择配方后，每轮自动打开配方并启动一次普通制作，然后执行整组宏。制作成功检查实际成品增加；没有材料、职业不符、制作失败或宏超时会停止。
- 默认四个主背包剩余空格 **≤10** 时前往 NPC 提交可交付的重建制作收藏品；只提交达到表内最低收藏价值的物品。
- 默认振兴票 **≥9000** 时兑换所选物品；提交前还检查奖励是否可能超过票数上限，必要时提前兑换。
- 兑换物品下拉框从**当前国服客户端数据表**读取名称和价格，支持搜索，可更换。购买后核对扣票及物品增加，按保留票数和背包容量限制购买。
- 提交和兑换使用固定柜台前站位，自动识别对应 NPC；制作点由玩家记录。
- 装备最低耐久严格低于10%时，自动使用暗物质自行维修，确认耐久恢复后继续制作。
- 使用 vnavmesh 的 IPC 计算路径和移动，返回制作点继续循环。区域改变、战斗、死亡、卡住、异常窗口或接口异常会停止。

## 编译与加载

需要 .NET 10 SDK、国服卫月 API 15 和兼容版本的 vnavmesh。构建脚本默认读取 `%APPDATA%\XIVLauncherCN\addon\Hooks\dev` 中的卫月依赖；请使用与自己游戏客户端匹配的依赖。升级客户端后需要重新编译和实测。

```powershell
.\build.ps1
```

也可显式指定依赖：

```powershell
.\build.ps1 -DalamudPath 'C:\path\to\matching\Dalamud'
```

输出 `dist\SkyLoop.dll`、`dist\SkyLoop.json` 和 `dist\SkyLoop.zip`。

发布维护者可运行 `./prepare-release.ps1`，生成仓库根目录的 `repo.json` 和 `dist/SkyLoop-版本.zip`；先上传对应版本的 Release 资源，再更新公开插件源。发布包包含 AGPL 许可证，对应源码位于同版本 Git 标签。

1. 游戏聊天输入 `/xlsettings`，在“实验性 / Experimental”的开发插件位置添加 **dist 中 SkyLoop.dll 的绝对路径**。
2. 输入 `/xlplugins`，点击“扫描开发版插件”，在开发插件列表启用“天穹循环 SkyLoop”。
3. 输入 `/skyloop` 打开界面。加载时默认停止，不会自动执行。
4. 在“宏队列”添加共通宏的编号并排序。如果一件物品需要两个宏，前一个选“宏执行结束”，最后一个选“本次制作成功”。
5. 在“循环制作配方”下拉框搜索并选择成品，插件每轮自动开始制作；选择“由宏自行启动制作”时，按宏自身流程运行。当前职业须与所选配方一致。
6. 在“背包与兑换”选择兑换物品，设置票数阈值和保留票数。
7. 在“NPC 与路线”记录返回制作点。提交与兑换 NPC 及交互位置已内置，无需配置；自动提交和兑换时须位于天穹街（区域886）。
8. 启用兼容国服版本的 **vnavmesh** 并等待当前地图网格就绪，再点击开始。`/skyloop stop` 可停止并取消本插件宏和移动。

## 验证范围与限制

已完成国服 API 15 引用编译及隔离的流程测试。可用 `dotnet run --project tests/FlowChecks/FlowChecks.csproj -c Release` 重跑流程检查，其他检查见 `tests` 与 CI 工作流。隔离测试使用模拟的客户端与服务，未覆盖实际游戏窗口回调。另已在游戏中验证连续制作两件、提交后增加63票，以及普通兑换确认后扣除40票并收到物品；这些记录不代表所有配方、角色与长时间完整循环均已验证。

- “宏执行结束”只表示游戏宏解释器结束；要判断动作结果，请用制作成功或物品增加。按配方循环制作时，最后一个宏必须配置结果条件。
- 自动提交限于 **伊修加德重建的制作收藏品**；不是采集物检品、普通收藏品交易或宇宙探索。
- 导航范围限于同一区域，不包括跨区传送、进入天穹街或自动切换职业。
- 配方必须能用当前职业制作。自行维修需要对应生产职业的已练等级及足够暗物质；插件不自动购材料、穿装备或选用额外食药。
- 本插件不会在 UI 布局不符时继续猜测点击；日志和状态栏会保留停止原因。
- 没有可提交收藏品、背包无法容纳兑换物、已持有独占物品、所选物品未解锁或未出售等情况会停止，需要调整配置。

- [官方 SamplePlugin 模板及开发插件加载说明](https://github.com/goatcorp/SamplePlugin)

- [国服 vnavmesh](https://github.com/AtmoOmen/ffxiv_navmesh-cn)
- [TheCollector](https://github.com/Ashylila/TheCollector)：仅研究 HWDSupply、ShopExchangeCurrency 等窗口交互思路，未复制其实现。
- [FFXIVClientStructs](https://github.com/aers/FFXIVClientStructs)：宏、背包、配方及 UI 结构参考；实际编译引用国服随卫月分发的版本。
- [Artisan 维修流程](https://github.com/PunishXIV/Artisan/blob/main/Artisan/Autocraft/RepairManager.cs)：参考正常自行维修指令、职业条件及暗物质替代规则，SkyLoop 独立实现维修状态和归属检查。

寻路采用 **NPC编号确定目标 + 固定交互站位确定终点 + 导航网格绕障**。只按屏幕 NPC 名牌前进容易受遮挡和视距影响；直接朝坐标直线移动则容易撞障碍。停止会取消本插件的待算路径和移动任务。

代码由 AI 辅助生成，供开发与测试；未提交官方插件仓库。分发的插件包仅包含本插件，卫月、FFXIVClientStructs、vnavmesh 与游戏数据由用户已有环境提供。
